Case study / Finance automation

Reconciliation and exception flagging tool

A script that matches transactions between an internal ledger and a bank statement automatically, and flags anything that does not line up, with a plain language reason attached to each exception.

The problem

At Meezan Bank, I reconciled over 200 client accounts by hand and built a compliance checklist after noticing the same errors recurring across a specific transaction type. That checklist caught issues before audit and became a team standard, but it was still a manual line by line check.

This project asks a simple question: how much of that manual reconciliation work can be automated, while keeping a human in the loop for the part that actually needs judgment, deciding what an exception means and what to do about it.

The approach

I built two mock datasets standing in for a general ledger export and a bank statement, since real client data cannot be used, with five deliberate mismatches planted across common real world reconciliation issues: an uncleared payment, a duplicate entry, a transposed digit, a timing gap between when a transaction was logged and when it cleared, and a bank fee that never made it into the ledger.

A Python script then matches every transaction by reference, and for anything that does not match cleanly, classifies why: missing on one side, a duplicate, an amount mismatch, or a timing difference, each with a short plain language explanation rather than just a flagged row.

I wrote the reconciliation logic myself and used AI to help write and debug the Python, the same way I use it in my day to day work now. Knowing what the tool needed to check and how to interpret the result was the actual work.

What it found

Run against 42 ledger entries and 41 bank entries, the script correctly identified all five planted exceptions and classified each one correctly:

ReferenceIssueLikely cause
GL-1014Missing on bankPayment logged but not yet cleared
GL-1022Duplicate entrySame transaction logged twice
GL-1030Amount mismatch90 EUR difference, likely a transposed digit
GL-1041Timing differenceSame amount, posted 4 days apart
BANK-FEE-01Missing on ledgerBank fee never recorded internally

One detail worth noting, the timing difference case was flagged with a note that a 4 day gap is longer than a normal settlement lag and worth confirming rather than dismissing automatically. The tool surfaces a judgment call instead of quietly assuming it is fine.

What I would extend next

  • Connect it to a live spreadsheet or a simple database instead of static CSV files, so it could run on a schedule.
  • Add an AI generated summary across all exceptions for a manager, not just a per line reason.
  • Track exceptions over time to spot recurring patterns, the same instinct that led to the original compliance checklist.

Tools used

Python, CSV based mock data, AI assisted development and debugging
